# 插件代码排查与性能复核（2026-11-08）

范围为主分支开发工作区；未访问生产实例。检查各模块主要入口、调用关系、异步操作、监听与清理路径，辅以单元测试和 Edge 无头浏览器回归，不代表所有宿主组合均已实测。

## 本轮修复

- 预设删除条目、创建分组、解散分组：弹窗返回后校验预设、设置对象、条目顺序、编辑版本、数据快照及编辑器存活状态，避免过期操作修改切换后的上下文。
- 运行时卸载及初始化失败：释放 Pinia store，避免重新初始化复用已解绑的设置实例和遗留响应式监听。
- 自动启动：捕获 activate 返回的 Promise 拒绝，记录初始化失败。
- 扩展目录排序：每个元素的 CSS order 每次排序只读取一次，避免比较器反复调用 getComputedStyle；保持相同 order 的稳定顺序。

## 验证与性能边界

- 异步操作测试覆盖弹窗期间切换预设、外部修改、销毁、禁用、替换顺序和继续编辑。
- 生命周期测试覆盖正常卸载、初始化失败、连续重新初始化以及异步启动报错。
- 排序测试使用 100 个元素，断言计算样式读取恰好 100 次且排序稳定。
- 既有浏览器回归覆盖 1280、800、390 像素，以及预设空闲不循环刷新、聊天内容更新不扫描世界书选择器。

仍值得实机测量的优化点：

1. 大量世界书的选择弹窗仍一次创建全部行；虽有 content-visibility，首次创建 DOM 的开销仍存在。需要真实库存规模的首次打开耗时后决定是否虚拟化。
2. 扩展设置目录监听整个布局的 class/style/childList。复杂扩展内部频繁变化可能触发额外目录同步；缩小监听范围需覆盖菜单精简器、动态抽屉、标题与隐藏状态的兼容行为。
3. 毛玻璃、多层阴影的 GPU 成本依赖设备、背景和 WebView。已有降特效选项，本轮未改变默认视觉。
4. 角色、扩展设置和部分 API 布局主要假定宿主根面板长期存在；整块根面板被第三方替换的组合仍需集成验证。

未测量 Tauri 实机 CPU、GPU、内存或帧率；没有声称整体性能提升百分比。世界书服务器缺少原子版本检查的并发保存限制仍存在，沿用代码中的 shortcut 说明。
